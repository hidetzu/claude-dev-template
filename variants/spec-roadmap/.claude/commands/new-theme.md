新しい Theme のステアリングディレクトリと 3 ファイル（requirements.md, design.md, tasklist.md）を作成します。

引数: $ARGUMENTS（`<YYYYMMDD>-<タイトル> <Themeの概要説明>`。例: `20260330-auth-layer 認証・認可の実装`）

## 実行手順

### 1. 引数のパース

- 第1引数: ディレクトリ名（`YYYYMMDD-タイトル`）
- 第2引数以降: Theme の概要説明

### 2. ディレクトリ作成

```bash
mkdir -p .steering/<ディレクトリ名>/
```

### 3. 事前調査

ファイル生成前に以下を確認し、内容に反映する:

- `doc/roadmap.md` — 該当フェーズの定義・スコープ
- `doc/functional-design.md` — 関連する既存機能
- `doc/architecture.md` — 技術方針・制約
- `doc/repository-structure.md` — 関連するディレクトリ・ファイル
- 直近の `.steering/` ディレクトリ — フォーマットの参考

### 4. ファイル生成

以下の 3 ファイルを生成する。概要説明と事前調査結果をもとに、具体的な内容を埋める。

#### requirements.md テンプレート

```markdown
# <Phase> <Theme名> — 要求定義

## 概要

<概要説明>

## 現状

- <現在の実装状態>

## 目標

- <達成すべきこと>

## スコープ

### 含むもの

- <実装するもの>

### 含まないもの

- <今回やらないもの>

## 受け入れ条件

- [ ] <テスト可能な条件>
- [ ] このプロジェクトのビルド・テスト・静的解析が通ること（コマンドは `doc/development-guidelines.md` に書く）
```

#### design.md テンプレート

```markdown
# <Phase> <Theme名> — 設計

## 実装アプローチ

<概要>

## 変更するファイル

| ファイル | 変更内容 |
|---------|---------|

## 変更しないファイル

| ファイル | 理由 |
|---------|------|
```

#### tasklist.md テンプレート

```markdown
# <Phase> <Theme名> — タスクリスト

- [ ] <タスク>
- [ ] ビルド・テスト確認
- [ ] 動作確認
```

### 5. 完了報告

作成したディレクトリとファイルの一覧を表示し、レビューを促す。
