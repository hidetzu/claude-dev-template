実装完了後に永続ドキュメント（`doc/`）の更新が必要かチェックし、必要なら更新します。

引数: $ARGUMENTS（省略可。ステアリングディレクトリのパス or ブランチ名。省略時は現在のブランチの変更から判断）

## 実行手順

### 1. 変更内容の把握

- 引数がステアリングパスなら、そのステアリングの requirements.md / design.md を読む
- 引数がブランチ名なら、`git diff main...<branch> --stat` で変更ファイルを確認
- 引数なしなら、`git diff main...HEAD --stat` で現在のブランチの変更を確認

### 2. 各ドキュメントのチェック

以下の各ドキュメントについて、更新が必要かを判定する:

#### doc/roadmap.md
- 新しいフェーズ / Theme が完了した場合 → ステータスを更新
- 新しいフェーズが定義された場合 → フェーズ体系テーブルに追加

#### doc/repository-structure.md
- 新しいディレクトリが追加された場合 → ツリーと役割テーブルに追加
- 新しい重要ファイルが追加された場合 → ツリーに追加

#### doc/functional-design.md
- 新しい機能が追加された場合 → セクション追加
- 既存機能の入出力が変更された場合 → 該当セクション更新

#### doc/architecture.md
- 新しいパッケージ / アーキテクチャパターンが導入された場合 → セクション追加
- 技術スタック / 依存関係が変更された場合 → 該当セクション更新

#### doc/glossary.md
- 新しいドメイン用語 / 技術用語が導入された場合 → 用語追加

#### doc/development-guidelines.md
- 開発フロー / 規約が変更された場合 → 該当セクション更新

### 3. 結果報告

以下の形式で報告:

```
## ドキュメント同期チェック

| ドキュメント | 更新要否 | 内容 |
|-------------|---------|------|
| roadmap.md | ✅ 不要 / ⚠️ 要更新 | <理由> |
| repository-structure.md | ... | ... |
| functional-design.md | ... | ... |
| architecture.md | ... | ... |
| glossary.md | ... | ... |
| development-guidelines.md | ... | ... |
```

### 4. 更新実行

ユーザーの承認後、必要なドキュメントを更新する。更新時は:

- 該当セクションのみを更新する（ドキュメント全体の書き直しは行わない）
- コードと矛盾する記述を残さない
- 既存のフォーマット・文体に合わせる
