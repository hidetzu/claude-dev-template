ステアリングファイルのレビューを行います。

対象: $ARGUMENTS（ステアリングディレクトリのパス。例: `.steering/20260330-auth-layer/`）

## レビュー手順

1. 対象ディレクトリ内の `requirements.md`、`design.md`、`tasklist.md` を読む
2. 以下の永続ドキュメントと整合性を確認する:
   - `doc/product-requirements.md` — プロダクト要件との整合
   - `doc/functional-design.md` — 既存機能設計との整合
   - `doc/architecture.md` — 技術方針との整合
   - `doc/roadmap.md` — ロードマップ上の位置づけ
3. 関連する既存コードを確認し、設計の実現可能性を検証する

## レビュー観点

### requirements.md
- 目標が明確か
- スコープ（含む/含まない）が定義されているか
- 受け入れ条件が実装判定可能なレベルか
- 既存機能への後方互換が考慮されているか

### design.md
- requirements の受け入れ条件を全て満たせる設計か
- 変更するファイル/変更しないファイルが明確か
- 既存コードとの接続点が具体的か
- テストケースが明示されているか（ある場合）

### tasklist.md
- design の変更ファイル一覧と一致しているか
- タスクの粒度が適切か（1タスク = 1コミット程度）
- ビルド/テスト確認がタスクに含まれているか

### 3ファイル間の整合性
- requirements の受け入れ条件 → design のアプローチ → tasklist のタスク が一貫しているか
- スコープ外と定義したものが design に混入していないか

## 出力形式

以下の形式でレビュー結果を出力:

```
## レビュー結果: [ステアリング名]

### 良い点
- ...

### 指摘事項（実装前に修正推奨）
1. ...

### 改善提案（任意）
- ...

### 判定
- [ ] そのまま実装に進んでよい
- [ ] 指摘事項の修正後に実装に進む
```
