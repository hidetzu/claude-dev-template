実装コードのレビューを行います。

対象: $ARGUMENTS（ブランチ名 or ファイルパス。例: `phase2-theme1-auth-layer` or `internal/auth/`）

## レビュー手順

1. 対象の変更差分を取得する
   - ブランチ名の場合: `git diff main...<branch>` で差分を確認
   - ファイルパスの場合: 指定ファイルを読む
2. 関連するステアリングファイル（`.steering/`）を特定し、設計との整合を確認する
3. 以下の観点でレビューする

## レビュー観点

### 設計との整合性
- ステアリングの design.md に記載された方針に沿っているか
- 変更するファイル/変更しないファイルが設計と一致しているか
- スコープ外の変更が混入していないか

### コード品質
- エラーハンドリングが適切か
- 型安全性が確保されているか（Go: interface{} の最小化、TS: any の回避）
- 既存コードのパターンに合っているか
- 不要なコメント・デバッグログが残っていないか

### テスト
- ステアリングに記載されたテストケースが実装されているか
- エッジケース（null, 空配列, エラー）が考慮されているか
- 既存テストが壊れていないか

### 後方互換
- 既存 API のレスポンス構造が壊れていないか
- 既存 UI コンポーネントが影響を受けていないか
- 既存のインポートパスが変更されていないか

### セキュリティ
- ユーザー入力のバリデーションが適切か
- XSS / インジェクションの懸念がないか

## 出力形式

以下の形式でレビュー結果を出力:

```
## 実装レビュー: [対象]

### 設計整合性
- ...

### コード品質
- ...

### テスト
- ...

### 指摘事項
1. [重要度: 高/中/低] ...

### 総合判定
- [ ] LGTM（そのまま進めてよい）
- [ ] 指摘事項の修正後に進める
```
